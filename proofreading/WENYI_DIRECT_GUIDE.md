# Wenyi Direct 翻译与校对方法

本文将 [`AlexbeatsZ/wenyi-direct`](https://github.com/AlexbeatsZ/wenyi-direct) 中与本项目直接相关的方法、信息边界和提示词原则整理为协作规范。

本文件不是要求所有协作者必须运行 Wenyi Direct，而是要求人工、Agent 或其他翻译工具在提交文本时遵守同一套质量标准。

---

## 1. 核心方法

### 1.1 章节／场景优先，而不是孤句优先

- 翻译前应读取足以判断说话者、指代、动作承担者和句间关系的上下文。
- 不要求先生成整部作品的摘要，也不依赖未来尚未处理的剧情。
- 长程信息只可来自已经确认的前文；不得把未来剧情提前写入当前译文。
- 剧本条目可以按固定索引分批写入，但理解范围应大于实际修改范围。

### 1.2 严格区分读取范围与写入范围

- **读取范围（read scope）**：为理解当前文本而查看的相邻原文、旧译、说话者和前文信息。
- **写入范围（write scope）**：本批被明确占用并允许修改的稳定条目索引。
- 可以读取占用范围外的相邻条目，但不得顺手修改未占用条目。
- 发现问题跨越批次边界时，应扩大占用范围或记录问题，不能越界提交。

### 1.3 不直接在正式文本上试错

- 校对建议先写入 `proofreading/reviewed-batch-*.json`。
- 只有通过结构检查和原文忠实度检查的修改，才同步到正式 JSON、Markdown、TXT 和 TSV。
- 原文、旧译、定稿和修改原因应能够追溯。

## 2. 推荐质量流水线

```text
直接翻译／现有译文
        ↓
原文事实审校
        ↓
局部统一修复
        ↓
纯中文阅读验收
        ↓
对阅读问题进行原文验证
        ↓
修改区域忠实度复核
        ↓
同步正式文本并合并
```

对于本仓库现有译文，通常从“原文事实审校”开始；若某条已经无法修补，也可以根据原文重新翻译。

### 阶段 A：直接翻译或重新翻译

目标：从原文重新建立语义，而不是在错误旧译上做词语替换。

必须做到：

- 通读可见上下文后再翻译。
- 日语原文应先还原省略主语、动作承担者、后置主语、指代、否定和句间关系。
- 按中文语序重新组织，不照搬日语连体修饰、名词句、后置补充和词性。
- 人物台词应像角色在当前情境中自然说出的话；低语、惊呼、命令和短促观察不能改成书面旁白。
- 可以保留破碎节奏，但不能留下主谓错位、不成立搭配、问句丢失或引语层级混乱。
- 不得把控制标记、说话者提示、范围标签和工具元数据写进译文。

### 阶段 B：原文事实审校

目标：判断中文是否准确表达原文，而不是进行无依据的文风改写。

逐项检查：

- 误译、漏译、增译；
- 主语、动作承担者和说话者；
- 指代、人物关系和代词性别；
- 否定、条件、比较、程度和时态；
- 数量、单位、方向、距离和物理动作；
- 术语、人名、组织名、武器名和称谓；
- 跨条目的句法连接与语义因果；
- 短句是否只是把词典义机械拼在一起。

事实问题必须有原文证据。不要把“我更喜欢另一种说法”当成事实错误。

### 阶段 C：纯中文阅读验收

目标：只从中文读者视角发现“语法似乎能解析，但真实中文中不成立”的问题。

验收时暂时不看原文和词库，只阅读读者最终能看到的中文，检查：

- 翻译腔和不成立搭配；
- 人物不会自然说出的台词；
- 主语或动作承担者突然错位；
- 上下条衔接断裂；
- 异常量词、标点和引号；
- 人物声音不一致；
- 节奏、对话功能或语气失真。

纯中文验收只能指出阅读问题，不能猜测原意。任何修复建议都应重新对照原文验证。

### 阶段 D：原文验证与局部修复

- 先判断中文阅读问题是否确实能在不损害原意的前提下修复。
- 修复范围可能大于症状所在的单条，应覆盖完整的因果区域。
- 不要只替换被指出的某个词；重新理解整个局部，再统一改写。
- 相邻上下文可以读取，但只修改明确允许写入的索引。

### 阶段 E：忠实度复核

对所有实际修改的条目逐一确认：

- 信息准确且完整；
- 未凭空增加事实、动作、心理或设定；
- 没有丢失否定、问句、命令、称呼和语气；
- 自然中文重组不应被误判为错误；
- `preferred` 词条未被采用，不能单独构成否决理由；
- 只有原文证据或有效的 `active hard` 规则可以作为术语类否决依据。

任何一个修改条目未通过，整批不得直接同步。

## 3. 术语规则

### 3.1 约束强度与生命周期分开

| 属性 | 含义 |
|---|---|
| `mode: hard` | 当前有效时必须采用；违反会阻止合并 |
| `mode: preferred` | 推荐的稳定译法，但允许按语境调整 |
| `status: active` | 可以进入当前翻译／校对依据 |
| `status: candidate` | 候选词条，尚未确认，不应强制使用 |
| `status: rejected` | 已否决，不得继续进入提示词或校对依据 |

### 3.2 不盲从词库

- 只有 `active hard` 才是默认强制规则。
- `active preferred` 只是建议，不得为了命中词库而制造误译或生硬中文。
- 若 `hard` 词条本身错误，应修改词库，而不是扭曲正文。
- 词条的适用章节、人物、语境或词义不明确时，应缩小适用范围。
- 一词多义的普通动词、形容词和描写词，不应仅因高频就加入强制词库。
- 术语分组只表示共享目标译名片段，不代表不同源词一定是同一实体。
- 代词提示只在命中词条的局部上下文中有效，不能跨后续条目持续推断人物性别或指代。
- `pronoun: neutral` 时不得主动补出“他”或“她”。

### 3.3 新词条的判断标准

适合加入词库：

- 明确的人名、组织名、地点名、武器名、能力名和制度名；
- 反复承担固定指称的称谓；
- 在本作中确实形成稳定设定含义的普通名词短语。

不适合直接加入强制词库：

- 只出现一次的普通描写；
- 依上下文变化明显的多义词；
- 单纯因为旧译使用过就被当成标准答案的词；
- 尚存在冲突或无法确认的候选译法。

## 4. 可直接使用的提示词骨架

以下是面向人工或 Agent 的精简版本。使用时应附上明确的读取范围、写入索引、原文、旧译、说话者和有效词库项。

### 4.1 翻译／重译提示词

```text
你是中文文学与游戏剧本译者。

通读全部只读上下文后，只翻译明确列出的可写条目。先根据原文还原省略主语、动作承担者、指代、后置主语、否定和句间关系，再按自然中文重组。

要求：
1. 忠实、完整，不增加原文没有的事实、心理、动作、程度或设定。
2. 台词必须符合说话者身份、关系、情绪和当前情境；不要把短促台词改成书面旁白。
3. 不照搬日语名词句、连体修饰、后置补充和词典义。
4. active hard 术语必须使用；preferred 只供参考，以当前语义和自然中文为先。
5. 词库若明显错误，应标记词库问题，不得迁就错误词条。
6. 不输出说话者元数据、控制标记、范围标签或只读条目。
7. 保持条目 ID、数量和顺序完全不变。
```

### 4.2 事实审校提示词

```text
你是文学翻译的事实审校员。

逐条比较原文与中文，只报告有原文证据的问题。检查误译、漏译、增译、主语、动作承担者、说话者、指代、否定、数量、时态、术语和跨条目语义关系。

短句也必须检查是否存在词典义直拼、不成立搭配、问句或命令功能丢失。不要进行纯粹的个人风格润色。

每个问题应给出：索引范围、问题类型、原文证据、必须保留的含义，以及实际需要统一修复的完整范围。
```

### 4.3 纯中文阅读验收提示词

```text
你只负责检查读者最终看到的中文，不查看原文、词库或翻译说明。

主动寻找：不成立搭配、翻译腔、不像人物会说的台词、主语错位、对话功能丢失、上下文断裂、异常量词、标点、引号、人物声音和节奏问题。

只报告确实影响理解、自然度、人物声音或连贯性的具体问题。不要猜测原意，不要把个人措辞偏好当成错误，也不要要求全面润色。
```

### 4.4 修复提示词

```text
根据已经通过原文验证的问题，在完整修复范围内重新理解并统一改写。

不要只替换被点名的词；同时检查相邻条目的主语、指代、动作顺序和对话衔接。只输出允许写入的稳定索引，不得修改只读上下文。

active hard 必须采用；preferred 仅供参考。若审校意见错误地把 preferred 当作强制规则，以原文语义为准。
```

### 4.5 忠实度复核提示词

```text
逐条验证所有实际修改的中文是否准确、完整，并且没有凭空增加事实。

自然中文重组不是错误。preferred 未采用也不是错误。只有原文证据或有效的 active hard 规则可以否决译文。

若任意修改条目不合格，整批判定为不通过，并指出可直接指导下一次修复的具体问题。
```

## 5. 本项目执行要求

- 当前正文已经存在，因此校对时应同时保留原文、旧译和定稿，而不是直接覆盖后失去差异依据。
- 每批工作先创建范围占用，再生成 `reviewed-batch` manifest。
- 只读上下文可跨越占用边界，但写入索引不得越界。
- 事实审校与中文阅读验收应作为两种不同视角；不要在一次含混的“润色”中混合完成。
- 中文阅读问题必须回到原文验证后才能修改。
- 词库新增、删除或模式调整必须记录原因。
- 同步脚本完成后，核对 JSON、Markdown、TXT 和 TSV 的同一条目内容一致。
- 合并后立即释放活动占用范围。
